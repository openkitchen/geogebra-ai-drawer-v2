## Design — Overview

### 背景与目标
我们在做一个“GeoGebra + AI”的教学助手：用户用自然语言提出几何/代数问题，系统生成并执行 GeoGebra 指令，最终给出**清晰、直观、可解释**的图形与文字说明。

本项目的第一优先级是**教学可读性**（尤其面向孩子/初学者），第二优先级是**生成稳定性**（可重复、可修复、无残留）。

### 核心用户体验目标（UX Goals）
- **图要“像教材”**：关键点/线/角必须标注，辅助元素不喧宾夺主。
- **几何题默认干净画布**：隐藏坐标轴/网格；代数题/坐标几何可显示。
- **出错要可恢复**：AI 第一次画错后，二次修正不留下错误图元残骸。
- **可自测、可回归**：同样输入在不同时间/模型下也能得到“足够相似、足够正确”的输出。

### 非目标（Non-goals）
- **不追求通用证明器**：我们不是在做形式化证明或自动定理证明。
- **不封装全部 GeoGebra API**：不会把 GeoGebra 的每个功能都在前端再包一层“工具函数集”。
- **不追求一次提示词解决所有问题**：提示词是主手段，但允许少量 deterministic 展示层规则兜底（见 `decisions.md`）。

### 成功标准（Success Criteria）
- **可读性**：图中关键对象有标签；角度弧清晰；不会出现重叠/难辨的多个数值标注。
- **可控性**：系统能明确判断“几何 vs 代数”并应用正确画布预设。
- **鲁棒性**：出现执行失败时，系统能回滚并重试；最终画面无“错误残留”。
- **可维护性**：新增一个教学场景（如勾股定理/中位线定理）时，主要通过 scenario/prompt + 自测用例完成，而不是新增大量前端特例代码。
